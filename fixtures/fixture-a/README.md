# 夹具 A：《雾港》

同人 v0.1 的评测夹具。它不是一篇要发表的小说，而是一份**带标准答案的合成短篇**：用来验证「场景契约 + lookup 能否降低硬违规」，以及检查器能不能在不误报的前提下抓住植入错误。

## 文件

| 文件 | 作用 |
|---|---|
| `source.md` | 原著正文，6 章约 4,000 字。事实、称呼、规则、秘密都从这里来 |
| `ground-truth.json` | 手写 canon：人物、事实、矛盾、世界规则、秘密、称呼矩阵、AU 规则、未声明私设、错字表、场景、检索问题 |
| `contracts/ch001..ch006.md` | 每章一份场景契约，9 段（视角/在场/称呼/知情/世界规则/时间线/禁忌/不确定/锚点） |
| `planted-errors/` | 15 份带标准答案的稿件：11 个植入错误 + 2 个干净对照 + 2 个必检补充样例 |
| `planted-errors/manifest.json` | 每个样例「应该被哪个 detector、以什么 code、什么严重度」命中的登记表 |

## 故事与 canon 要点

- 三个人物：**沈砚**（主角，守灯人学徒，左眉旧疤，父亲沈九三年前在雾里失踪）、**裴照**（巡雾队副队长，ch001 叫「沈先生」，ch002 起改口「阿砚」）、**苏鹤**（档案房记录员，瞒着秘密）。
- 一个秘密：沈九没有死，每年冬至在雾里给塔上送灯油。知情顺序：苏鹤 ch003 → 沈砚 ch004 → 裴照 ch005；对话里 ch004 之前不许说破。
- 一组称呼变化：裴照对沈砚，公开「沈先生」只在 ch001，ch002 起私下「阿砚」；「小砚」是忌讳。
- 一处设定矛盾：沈砚的眼睛，ch002 写「浅褐色」，ch005 写「灰蓝色」，未裁决。写作时**不许断言任何一种颜色**。
- 两条世界规则：潮声钟响时不许出声走动；涨雾日封港。
- 另加一章干净对照（ch006，裴照 POV 的日常夜巡），只用来统计误报，不参与「5 场景 × 3 臂」的 45 篇。

## 8 类植入错误

| 类别 | 样例 | 检测器 | 严重度 | v0.1 角色 |
|---|---|---|---|---|
| 错外貌 | e01（疤在右眉） | `appearance` | blocker | 必检 |
| 错称呼 | e02（改口后仍叫沈先生）、e02b（叫忌讳的「小砚」） | `address` | blocker | 必检 |
| 提前知情 | e03（叙述）、e03b（对话） | `knowledge` | blocker | 必检 |
| AU 规则泄漏 | e04（「亡者的声音」） | `auLeak` | blocker | 必检 |
| 标签违约 | e05（正文干净但标成私设） | `tagDefault` | blocker | 必检 |
| 20 字复制 | e06（逐字抄原著 26 字） | `copy20` | warning | 候选 |
| 分支串线 | e07（「在 IF 线里……」） | `branchCross` | info | 候选，v0.1 不拦 |
| 未声明私设 | e08（「苏鹤其实是沈九的女儿」） | `headcanon` | warning | 候选 |

另有 3 个补充检测器（不在启动卡的 8 类里，但检查器已实现）：`unknown`（断言未裁决的眼睛颜色，e09）、`worldRule`（潮声钟响时开口喊，e10）、`name`（把「沈砚」写成「沈研」，e11）。

## 怎么用

```bash
node scripts/fanfic-eval.mjs verify     # 夹具自检：引文、契约、场景、manifest
node scripts/fanfic-eval.mjs check      # 15 个样例逐一比对标准答案
node scripts/fanfic-eval.mjs lookup --all   # 10 个检索问题
```

`check` 的通过标准：

- 15/15 样例命中登记过的 detector + code；
- 必检 5 类的样例 7/7 命中；
- `clean-1`、`clean-2` 零 finding；
- 每条 finding 都带「在哪（偏移/引文）、凭什么（why）、跟哪条设定冲突（canonRef）」。

## 改夹具的规矩

1. `source.md` 是唯一事实来源。`ground-truth.json` 里每条 `quote` 必须能在对应章节逐字找到，`verify` 会失败否则。
2. 加一个植入错误：写文件 → 在 `manifest.json` 登记 `class`、`scene`、`expect`。检查器必须按登记命中，不能靠「顺手多报几条」通过。
3. 加一个场景：在 `ground-truth.json.scenes` 增加条目，并补 `contracts/<chapter>.md`；契约必须 9 个标签、不超过 800 字。
4. 眼睛颜色的矛盾**先别裁决**。v0.1 要验证的正是「知道这是未定事实时，模型会不会瞎断言」；裁决之后 `unknown` 检测就失效了。
5. 改完跑 `verify` + `check` + `npm test`，数字进验收文档。

> **这是合成测试数据，不是抓取来的同人作品。** 沈砚、裴照、苏鹤与《雾港》全文都是为本项目评测手写的，事实、引文、时间线是 ground truth。它只服务评测与单测；生产使用走 `/fic import <自己的文件>`，不依赖它。如果不再需要跑评测，整个 `fixtures/` 目录可以删除（同时要删依赖它的约 40 个测试与 `runs/` 产物）。
